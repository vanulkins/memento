# Артефакты тестирования аудиофайлов

[`results.csv`](results.csv) содержит результаты проверки локального распознавания и диаризации Memento. Это не список UI-проверок и не отчёт о тестировании всего приложения.

## Что считается одним тестом

Для каждого теста используются три логических файла:

1. исходный MP3;
2. вручную подготовленный эталонный JSON с правильными словами, границами реплик и говорящими;
3. JSON аналитики, экспортированный из Memento после импорта и полной обработки MP3.

Эталон создаётся до запуска приложения и не строится из результата Memento. Идентификаторы говорящих могут называться по-разному, поэтому перед сравнением выполняется взаимно-однозначное сопоставление спикеров по максимальному пересечению их временных интервалов.

## Формат эталона и результата

```json
{
  "transcript": [
    {
      "speaker_id": "speaker_1",
      "start_ms": 1250,
      "end_ms": 4380,
      "text": "Добрый день!"
    }
  ]
}
```

Обязательные поля каждой реплики: `speaker_id`, `start_ms`, `end_ms` и непустой `text`.

## Процедура

1. Зафиксировать SHA-256 и размер исходного MP3.
2. Импортировать файл через системный Android-пикер.
3. Дождаться завершения локального распознавания и диаризации.
4. Скачать аналитику встречи в JSON.
5. Проверить схему и монотонность временных меток.
6. Сопоставить идентификаторы говорящих с эталоном.
7. Сравнить текст, число спикеров, границы и принадлежность реплик.
8. Повторить экспорт после полного перезапуска приложения и проверить стабильность `speaker_id`.

Сравнение включает WER для слов, ошибку определения говорящего, число пропущенных и лишних спикеров, среднюю ошибку границ реплик, пустые/односимвольные реплики и временной охват аудио. `success=true` означает ожидаемый результат; для тишины и повреждённого MP3 это корректная обработка без падения. `checksum_match` подтверждает неизменность импортированного MP3.

## Поля CSV

- `commit` — версия приложения;
- `file_name`, `file_size_bytes`, `duration_seconds` — входной MP3;
- `distance_meters=0` — прямой импорт файла, а не запись через микрофон;
- `noise_condition` — характер исходной записи;
- `noise_level_db=n/a` — уровень шума не измерялся отдельным шумомером;
- `attempt` — первичная или повторная проверка;
- `device_tx` — хранилище фикстуры;
- `device_rx` — устройство обработки;
- `notes` — эталон, экспорт и измеренные характеристики.

Набор включает реальные и синтетические записи на 1, 2 и 4 говорящих, повторную проверку после перезапуска, тишину и повреждённый MP3. Это небольшой воспроизводимый набор, а не полноценный отраслевой бенчмарк.
